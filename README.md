# СВЯЗКА — версия 2026.10.10

Единый проект для карьеры, работодателей и рекламных заявок. В комплекте исходники, собранный сайт `dist/`, сервер, тесты и примеры запуска. Оператор: **ИП Шелопугин Никита Матвеевич**. Реквизиты в `src/config/legal.ts` сохранены из исходного проекта; контактный email, адрес и домен задаются при установке.

## Быстро открыть готовую сборку

1. Установите **Node.js 24 LTS**.
2. Распакуйте архив **в новую пустую папку**. Перейдите в папку `project`, где находится `package.json`.
3. Запустите `npm start` или `start.cmd` на Windows / `./start.sh` на Linux.
4. Откройте **http://127.0.0.1:3001**.

Предварительная установка npm-зависимостей для готовой сборки не нужна: сервер использует встроенные модули Node. Вход по email и паролю работает сразу. База `data/platform.sqlite` создаётся автоматически. Сайт начинает с пустых профилей и вакансий; каталоги услуг и VK-размещений уже заполнены. Чужие реальные вакансии не выдаются за действующие объявления.

Чтобы изменить код и пересобрать:

```bash
npm ci
npm run dev
# Разработка: http://localhost:5173; API: http://127.0.0.1:3001
npm run build
npm test
npm start
```

`npm run dev` запускает API и Vite вместе. После изменений серверных доменных модулей в `src/repositories` и расчётов перезапустите dev-команду: она заново генерирует серверные модули. `npm run build` обновляет и сервер, и клиент. Vite без API или размещение одного `dist/` на статическом хостинге не обеспечивают работу кабинетов.

## Где и что заменять

Надёжный вариант — использовать новую папку целиком, сохранив старую рядом. Если переносите в существующий проект, сначала сделайте его резервную копию:

| Путь | Действие |
|---|---|
| `src/` | Заменить папку целиком новой версией. Не объединять с устаревшими `copy` файлами. |
| `public/` | Заменить комплектом из архива. |
| `server/`, `scripts/`, `tests/`, `deploy/` | Добавить новые папки целиком. |
| `package.json`, `package-lock.json`, `vite.config.ts` | Заменить новыми файлами. |
| `tsconfig*.json`, `index.html`, `Dockerfile`, `compose.yaml` | Использовать версии из архива. |
| `dist/` | Использовать готовую сборку или заново выполнить `npm run build`. |
| `.env` | Сохранить отдельно, сверить с новым `.env.example`. Старые Supabase-параметры не нужны для основного сервера. |
| `data/` | Если уже запускали эту версию, сохранить: здесь ваша база. Не заменять при обновлении. |

Не выбирайте «сохранить оба файла» при копировании: это создаёт `App copy.tsx` и повторяет прежнюю проблему. Внутри архива нет `node_modules`, реального `.env`, базы пользователей и дубликатов.

Основной сервер этой версии использует SQLite. Данные прежних демо в браузере и внешней базы Supabase автоматически не импортируются. Старый проект и его настройки сохраняйте отдельно; перенос существующих пользователей требует отдельного экспорта и миграции. В этой версии зарегистрируйте аккаунт заново.

## Администратор

Сначала зарегистрируйте свой аккаунт через сайт. Затем в терминале из папки проекта:

```bash
npm run admin -- your-email@example.org
```

Перезайдите в аккаунт и откройте `/admin`. Права хранятся в базе. Команда работает только на сервере с доступом к файлу базы; регистрация с известным email сама по себе не даёт административных прав. Отозвать доступ:

```bash
npm run admin -- your-email@example.org revoke
```

Для Docker: `docker compose exec app npm run admin -- your-email@example.org`.

## Рабочие сценарии

- Аккаунт: регистрация, вход, выход, серверная сессия, отдельные права администратора и участников организаций.
- Карьера: профиль за три шага; отдельные резюме под разные вакансии; опыт, образование, навыки, языки, портфолио, зарплатные ожидания; автосохранение; предпросмотр; PDF с кириллицей; приватность и публичная ссылка `/r/:slug`.
- Компании: кабинет с реквизитами и командой; публичная страница с описанием, условиями и вакансиями; поиск компаний. Финансовые и личные сведения не входят в публичный ответ API.
- Вакансии: создание и редактирование; черновик → модерация → одобрение → публикация; поиск, фильтры и избранное; отклик с резюме и письмом; смена статуса работодателем; отзыв кандидатом. Изменение опубликованной вакансии возвращает её на повторную модерацию. Отозванный отклик закрывает работодателю просмотр резюме через специальный API.
- Услуги: каталог → выбранная услуга → создание организации, если нужно → заявка → кабинет и администрирование проекта. Источник заявки сохраняется через вход.
- Реклама: 14 форматов VK для ВГУ, ERROR, КРЕАТОРА и СТУДКАРЬЕРЫ; медиаплан; единая заявка. Цены сервер берёт из каталога, подмена цены в браузере не меняет итог.
- Документы: создание, редактирование текста, сумма, статус учёта, просмотр и скачивание печатного HTML. Откройте файл в браузере и сохраните PDF через печать. Статус «подписан» отражает подписание вне системы, электронная подпись не реализуется этой отметкой.
- Тесты: ответы проверяются и оцениваются сервером; результаты сохраняются; повторное прохождение ограничено 30 днями. Это опросники интересов и предпочтений, не подтверждение профессиональной квалификации.
- Партнёрство: настоящие реферальные ссылки, переходы, регистрации, история начислений; бонусы за первое резюме и отклик. Бизнес-бонусы подтверждает оператор; автоматического вывода денег нет.
- Согласия, уведомления и одноразовые приглашения в команды сохраняются на сервере.

## Пилотный прайс VK

Редактировать: `src/data/advertisingPlacements.ts`, затем `npm run build`.

| Сообщество | Пост | История | Пост + 2 истории | Нативная интеграция |
|---|---:|---:|---:|---:|
| ВГУ — vk.ru/vsumain | 10 000 ₽ | 4 000 ₽ | 13 000 ₽ | По отдельной смете |
| ERROR — vk.ru/careererror | 4 500 ₽ | 1 800 ₽ | 5 900 ₽ | 7 500 ₽ |
| КРЕАТОР — vk.ru/careercreators | 2 500 ₽ | 1 000 ₽ | 3 200 ₽ | По отдельной смете |
| СТУДКАРЬЕРА — vk.ru/sovetcareer | 2 000 ₽ | 900 ₽ | 2 600 ₽ | По отдельной смете |

Это стартовые предложения проекта, а не проверенные публичные тарифы администраций VK. Даты и смета подтверждаются оператором. Непроверенные показатели охвата не показываются как гарантированные. ВГУ требует редакционного согласования.

Сумма обычных размещений считается по прайсу без автоматических надбавок из калькулятора таргета. Для таргетированной рекламы сохранена расчётная модель исходного проекта: ставка площадки 22% и ведение 20% от бюджета без НДС. Она отдельно тестируется; перед реальными договорами проверьте ставку конкретной площадки и налоговый режим оператора. Не добавляйте НДС из этой модели к каждой нативной публикации.

## Настройка внешних сервисов

Скопируйте `.env.example` в `.env`. В локальной разработке оставьте `PUBLIC_ORIGIN` пустым.

Для production задайте `PUBLIC_ORIGIN=https://ваш-домен` и `COOKIE_SECURE=true`. Используйте один домен для сайта и API. Заполните `VITE_LEGAL_EMAIL`, `VITE_LEGAL_ADDRESS`, `VITE_PRODUCTION_DOMAIN` и пересоберите клиент. В комплекте юридические документы остаются **проектами**: их содержание и реквизиты нужно утвердить перед публичным использованием.

VK ID необязателен: укажите одинаковый ID приложения в `VK_APP_ID` и `VITE_VK_APP_ID`, адрес callback в `VITE_VK_REDIRECT_URL`, разрешите домен в настройках VK и выполните `npm run build`. Готовая переносимая сборка из архива использует вход по email; VK включается при пересборке с вашей конфигурацией. Сервер проверяет access token через `user_info`, не доверяет VK ID из запроса клиента.

DaData необязательна: `DADATA_API_KEY` хранится только на сервере. Без ключа реквизиты заполняются вручную. Старые Supabase edge functions сохранены для совместимости, основной клиент использует `/api/lookup/*` нового сервера.

## Развёртывание

Обычный сервер: выполните сборку, настройте `.env`, запустите Node как службу и проксируйте HTTPS-домен на `127.0.0.1:3001`. Пример `deploy/Caddyfile` требует замены домена. Сохраняйте `data/` на постоянном диске.

Docker:

```bash
# Создать .env из .env.example, заполнить параметры
# Команда создаёт контейнер только на вашем сервере
docker compose up -d --build
```

База хранится в отдельном volume `platform-data`. Не удаляйте его при обновлении. Это один сервер с SQLite; для нескольких независимых API-инстансов нужна отдельная архитектура общей базы. В этот комплект не входит перенос на вашу внешнюю инфраструктуру.

Резервная копия работающей базы:

```bash
npm run backup -- ./backups/platform.sqlite
```

## Проверки и границы готовности

`npm test` запускает интеграционные проверки реального HTTP API, хранения, доступа, расчётов и PDF. `docs/AUDIT_2026-10-10.md` содержит фактический результат этого прогона.

Браузерный сценарий находится в `tests/browser/run.mjs`. Он **не был выполнен в среде подготовки**, поскольку Chromium недоступен для загрузки. Для запуска на своём компьютере:

```bash
cd tests/browser
npm install
npx playwright install chromium
npm test
```

По умолчанию сценарий сам запускает сервер с временной тестовой базой и удаляет её после завершения. Требуется готовая сборка проекта. Если задаёте `TEST_URL`, сценарий создаёт аккаунты в указанной системе: используйте только тестовый сайт.

Не выполнена внешняя проверка VK ID и DaData с вашими рабочими ключами. Оплата, электронная подпись, отправка писем, автоматическая публикация в VK и проверка личности родителя по документам не подключены. Рекламные размещения, услуги и оплаты обрабатывает оператор через заявки и статусы; подтверждение родителя записывает декларацию согласия, а не удостоверяет личность. Работоспособность каждого внешнего сервиса нельзя подтвердить без его настройки и доступа.
